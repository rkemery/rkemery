### Richard K.

I build and measure LLM systems. These five repos cover evals, RAG, fine-tuning against prompting, multi-agent workflows and guardrails, mostly on a fictional neobank's support desk. Every result comes with a 95% confidence interval, a sample size and what it cost, and every README regenerates its results offline from committed records, with no keys.

| Repo | What it shows | Headline result |
|---|---|---|
| [llm-eval-harness](https://github.com/rkemery/llm-eval-harness) | A small eval toolkit: one results format, clustered error bars, paired tests with minimum detectable effects, a checklist judge and a CI gate. The other four repos build on its records, stats and model clients. | Interval coverage checked by simulation (95 to 97% at 8 clusters). |
| [rag-support-assistant](https://github.com/rkemery/rag-support-assistant) | Instrumented RAG over a 151-article help center, with a retrieval grid, abstention and hallucination metrics, and two LLM judges validated on perturbations with known labels and on RAGTruth. | Convex hybrid fusion was the only retrieval step that beat dense retrieval (+0.029 nDCG@10, p = 0.004). Putting the whole corpus in the prompt tied the best retrieval arm on accuracy at 2.6x the cost. The judges caught 100% of synthetic errors but only 59% and 64% of RAGTruth's hallucinations. |
| [banking77-lora-vs-frontier](https://github.com/rkemery/banking77-lora-vs-frontier) | LoRA on a 0.6B model trained on a small CPU, QLoRA on an 8B model on one GPU, and prompting frontier API models, on Banking77 intent classification. | gpt-6-sol with retrieved examples beat the CPU-trained 0.6B LoRA by 1.2 points (95.0% vs 93.8%, p = 0.001), at $1.43 per 1,000 predictions against the LoRA's $0.0061. A logistic regression on frozen embeddings that trains in 2 seconds landed within 1.2 points of the LoRA. |
| [support-triage-agents](https://github.com/rkemery/support-triage-agents) | A LangGraph triage graph with typed handoffs, human approval and a SQLite bank, against a single agent with the same tools, on 50 tickets checked by code. | The graph resolved 81.5% of tickets against 64.5% (p = 0.009) and cut policy violations from 9% to 0%. Most of the gap came from the single agent answering without looking anything up. |
| [guarded-llm-gateway](https://github.com/rkemery/guarded-llm-gateway) | A FastAPI gateway with PII redaction, injection detection, output rules, rate limits and model fallbacks, measured on public attack sets. | The injection detector caught 86.9% of untransformed direct injections at a 1% false positive rate. Its base64 and leetspeak catches come from the format, not the attack. |

Each README leads with what was found, then says what didn't work and what the numbers can't show. The code was written with Claude Code as a pair programmer, under my direction and review.
